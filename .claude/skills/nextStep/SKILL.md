# /nextStep — tinytowngen を 1 ステップ改善する

引数: 任意。BACKLOG の番号やキーワード（例: `/nextStep 3`, `/nextStep canal`）。新しいアイデアを文章で渡された場合は、まず BACKLOG の「未着手」に追記してからそれを対象にする。

## 手順

1. **現状把握**
   - `BACKLOG.md` と `CLAUDE.md` を読む。
   - `swift build` と `swift test` を実行し、開始時点でグリーンか確認する。赤ならまずそれを直すことを今回のステップにする。
2. **対象を決める**
   - 引数があればそれ、なければ「未着手」の先頭。
   - 1 回の実行で扱うのは 1 項目だけ。大きすぎる場合は分割して BACKLOG を書き換え、最初の小片だけ実装する。
   - 配置文法（パラメーター書式）を変更・追加する場合は、既存の書式との後方互換を保つ。互換を壊す必要があるときは実装前にユーザーに確認する。
3. **実装**
   - パイプライン（`LayoutParser` → `Planner` → `Renderer`）の該当層だけを変更する。検証ロジックは `Planner`、描画は `Renderer` に置く。
   - `Resources/` を変更したら `Scripts/embed-resources.sh` で埋め込みを再生成する（`EmbeddedResources.swift` は手で編集しない）。
4. **テスト**
   - 追加・変更した挙動に対するテストを `Tests/TinyTownCoreTests/` に追加する（正常系 + エラー系）。
   - `swift test` が全件パスするまで直す。
   - 描画を変えると `GoldenImageTests` が失敗する。失敗メッセージの PNG を Read で見て、意図通りの変化であることを確認してから新しいハッシュに更新する（見ずに更新しない）。意図しないケースが変わった場合は実装を直す。
5. **目視確認**
   - 変更が描画に関わる場合、スクラッチパッドに `--scale 4` で PNG を出力し、Read で画像を見て確認する。変更前後を比べられる例を選ぶ。
6. **ドキュメント同期**
   - 文法・オプション・エラー・候補数を変えたら `CLI.helpText`（`--help`）と `README.md` を両方更新する。`--help` は他の AI エージェントが読む前提なので、書式・例・エラー条件を省略しない。
7. **BACKLOG 更新**
   - 完了した項目を「完了」に移し、`YYYY-MM-DD: 内容` の形で記録する。
   - 作業中に見つけた新しい改善点は「未着手」に追記する。
8. **報告**
   - 何を変えたか、テスト結果、確認した画像（パス）、次の候補を簡潔に報告する。コミットはユーザーに頼まれた場合のみ行う。
